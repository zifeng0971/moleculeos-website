# MOS Agent：以 coding agent 形态重构 MOS

> 原型路由：`/studio`（`components/studio/`）。数据为前端模拟，3D 使用真实 2FJG 结构与 Mol*。

## 为什么是 coding agent 的形态

现有 MOS 把功能铺在工具栏、弹窗表单、Task 列表、通知和 Mocha 面板里，用户要先懂模型名才能开始。Coding agent（Claude Code、Cursor 一类）证明了另一种组织方式门槛更低：**对话是唯一入口，agent 把计划、每一次工具调用和产出文件都摊开给你看**，你只需要描述目标并在关键处确认。

MOS 天然适合这个形态：模型调用就是“工具调用”，结构 / 打分表就是“文件”，选中残基就是“选中代码”。

## 对应关系

| Coding agent | MOS Agent |
| --- | --- |
| 会话列表（按仓库分组） | 会话列表（按研究项目分组），运行中的会话有状态点 |
| 计划 / Todo 清单 | 研究计划清单，逐项打勾 |
| 工具调用（Bash、Edit…）可展开看参数与输出 | 模型调用（MMFold、亲和力扫描…）可展开看参数、运行日志、结果与**数据来源**，可复制参数复现 |
| 执行前询问权限 | **算力确认**：显示预计 GPU 时长与积分；可选“运行 / 本会话都允许 / 跳过” |
| 权限模式 | 运行模式：计算前确认 / 自动执行 / 只出计划 |
| 编辑器标签页打开文件 | 右侧工作台标签页：`.cif` 结构（3D + 序列条）、`.csv` 表格（可排序、点行定位） |
| 选中代码作为上下文 | 在 3D 或序列条上选中残基，自动作为上下文附在输入框 |
| `/` 命令、`@` 引用文件 | `/fold` `/scan` 等直接调用模型；`@CDR-H3` `@链 H` 引用区域 |
| 停止按钮 | 随时停止，未确认的计算不会发起 |

## 科研场景的专门设计

- **残基即链接**：回答中的 `H:99` 等残基是可点击的标签，点一下就在 3D 中选中并聚焦。
- **序列按代码块渲染**：粘贴 FASTA 后自动识别链类型（框架区保守基序判断重链 / 轻链 / 抗原），按 10 位分组带编号。
- **结果先用图说话**：突变扫描以“位点 × 20 种氨基酸”热图内联在对话中；候选清单内联表格带“推荐 / 可能失稳”标记。
- **置信度始终可见**：预测结构默认按 pLDDT 着色，agent 会主动指出低置信区域并提醒谨慎结论。
- **可追溯**：每次模型调用记录模型版本、输入哈希与参数；产出文件出现在侧栏“产出文件”中。
- **着色透镜**：同一结构可在置信度 / 区域 / 界面 / ΔΔG 之间切换，序列条下方色带同步。

## 原型中可体验的流程

1. 新会话首页点“从序列预测复合物结构”→ 发送 → 识别 3 条链 → 计划 → MMFold 等待算力确认 → 运行 → 打开 `g6_vegf_model_1.cif` → MMetrics 解析界面 → 总结与建议。
2. 点建议“扫描界面位点，找提升亲和力的突变”→ 热图 → `affinity_scan.csv` → 稳定性打分 → 候选表与 `candidates.csv`。
3. 在序列条上拖选几个残基，再提问：选区会作为上下文发送，agent 针对选区回答。
4. 运行模式切到“只出计划”：agent 只给计划，点“按这个计划执行”再开始。

## 待验证

- 真实 Mocha 后端的流式事件能否映射为这几类块（文本 / 计划 / 工具调用 / 文件 / 图表）。
- 长时间任务（数小时）下会话的离开与回来：需要通知与“会话恢复”。
- 专家用户的快捷路径：除了对话，是否保留直接在工作台发起模型的入口。
