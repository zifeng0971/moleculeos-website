Persists sequences in a project-local FASTA library and performs every sequence operation programmatically. 4 --- 5 6 # Sequence Toolkit 7 8 A single-command toolkit for protein sequence operations. All operations run 9 through `sequence_toolkit.py`, use a project-local directory of per-record 10 FASTA files, and emit typed JSONL records on stdout (FASTA/TSV where noted). 11 12 Invoke the toolkit as `python <<skill_dir>>/sequence_toolkit.py`; 13 `<<skill_dir>>` is this skill's directory — the `Path:` of this SKILL.md in 14 the system prompt's skill listing. 15 16 ## Requirements 17 18 Python >= 3.11. All dependencies (`requests`, `gemmi`, `biopython`) 19 are pre-installed in the Mocha sandbox — do not install anything. If an import 20 error nonetheless occurs, report it to the user instead of installing packages. 21 22 `gemmi` is only needed for `fetch-pdb`, and `biopython` only for 23 `compare`/`identify` and `store --crc64`; both are imported lazily, so the 24 other subcommands work without them. 25 26 ## Global Option 27 28 ```bash 29 --library <<path>> Sequence library directory (default: auto-detected, see below) 30 ``` 31 32 `--library` is a global option and must precede the subcommand: 33 34 ```bash 35 python <<skill_dir>>/sequence_toolkit.py --library <<path>> <<subcommand>> ... 36 ``` 37 38 ## Library Location 39 40 The library directory is resolved in this order: 41 42 1. `--library <<path>>` always wins. 43 2. If `/workspace` exists (the agent's default working environment), the 44 library is `/workspace/.mocha/seq_lib`. 45 3. Otherwise the location recorded by `init` (or chosen at an interactive 46 prompt on first use) is used. 47 48 When `/workspace` does not exist and nothing is recorded yet, an interactive 49 run prompts for a directory; non-interactive runs fail with instructions. 50 51 ### `init` 52 53 Create `seq_lib` inside a chosen directory and record it as the default 54 library location. The location is recorded in 55 `~/.config/sequence-toolkit/config.json`, so `init` needs write access to the 56 home config directory. 57 58 ```bash 59 python <<skill_dir>>/sequence_toolkit.py init <<project_dir>> 60 ``` 61 62 ## Subcommands 63 64 ### `fetch-uniprot` 65 66 Fetch the canonical sequence for a UniProt accession. 67 68 ```bash 69 python <<skill_dir>>/sequence_toolkit.py fetch-uniprot <<accession>> [--id <<id>>] [--force] 70 ``` 71 72 ### `fetch-pdb` 73 74 Fetch PDB chain sequences. Omit `--chain` to fetch every protein chain of the 75 entry — one record per chain, named `<<pdb_id>>_<<chain>>`; pass `--chain` for 76 a single chain (`--id` is only valid together with `--chain`). RCSB downloads 77 are brought into MOS layout first (chains relabeled A, B, C…, residues 78 reindexed to entity-sequence numbering), so chain references match MOS 79 objects; the summary's `chains` list gives each chain's MOS label, original 80 author label, and entity, and author labels are accepted as input — they are 81 translated with a warning. Local files supplied via `--cif` or `--pdb` 82 (mutually exclusive) keep their own layout. 83 84 The stored record preserves unresolved (unmodeled) residues as `-`, keeping 85 positions aligned with the structure. When unresolved residues exist, a second 86 record `<<id>>_full` is stored alongside, containing the complete entity 87 sequence with real residue letters at every position. The summary reports 88 `unresolved` (gap count), `unresolved_ranges` (1-based range syntax), and 89 `full_id` when the second record was created. 90 91 When using a PDB-derived chain as a sequence payload, check `unresolved` in 92 the summary: if greater than 0, use the `<<id>>_full` record so residues missing 93 from the structure are still included. 94 95 ```bash 96 python <<skill_dir>>/sequence_toolkit.py fetch-pdb <<pdb_id>> [--chain <<chain>>] [--id <<id>>] [--cif <<cif_path>>] [--pdb <<pdb_path>>] [--force] 97 ``` 98 99 ### `store` 100 101 Store a raw sequence or the first record of a FASTA file under a library ID. 102 Existing IDs require `--force` to overwrite. 103 104 **Prefer `--fasta` for long sequences** to avoid LLM transcription errors. 105 `--seq` is intended for short fragments: pastes longer than 50 residues are 106 **rejected** unless verified with at least one of: 107 108 - `--length <<residue_count>>` — expected residue count, taken from the user or source 109 metadata (not counted by the agent) 110 - `--crc64 <<hex>>` — UniProt CRC64 checksum of the sequence 111 112 Whitespace inside `--seq` is stripped, so long sequences can be pasted one 113 chunk per line, which lowers transcription error rates. 114 115 A failed `--length`/`--crc64` check means the paste is corrupted. Recover by 116 re-deriving from the source (`get` ranges → FASTA → `store --fasta`), not by 117 recounting residues or adjusting characters by hand. 118 119 **Never abbreviate or truncate the sequence** (no `...`): paste every residue, 120 transcribing directly from the user's source. 121 122 ```bash 123 python <<skill_dir>>/sequence_toolkit.py store --seq <<sequence>> --id <<id>> [--force] 124 python <<skill_dir>>/sequence_toolkit.py store --seq <<sequence>> --length <<residue_count>> --id <<id>> 125 python <<skill_dir>>/sequence_toolkit.py store --fasta <<fasta_path>> --id <<id>> [--force] 126 ``` 127 128 ### `get` 129 130 Retrieve a full sequence or segments. Ranges use 1-based inclusive syntax: 131 comma-separated positions and hyphenated ranges. 132 133 Output defaults to FASTA — one record per range; comma-separated segments are 134 returned as separate records, never concatenated. Use `--format jsonl` for 135 typed segment records. 136 137 To save a sequence to a file, pass `--output <<path>>`: the file receives pure 138 FASTA and nothing else. Do not redirect stdout — the closing JSONL summary 139 record would land in the file too. 140 141 ```bash 142 python <<skill_dir>>/sequence_toolkit.py get <<id>> 143 python <<skill_dir>>/sequence_toolkit.py get <<id>> <<ranges>> 144 python <<skill_dir>>/sequence_toolkit.py get <<id>> --output <<fasta_path>> 145 python <<skill_dir>>/sequence_toolkit.py get <<id>> <<ranges>> --format tsv # or jsonl 146 ``` 147 148 ### `compare` 149 150 Compare two sequences with Needleman-Wunsch global alignment and emit the 151 mutation report. Sequences longer than 5000 residues are rejected. 152 153 Use `compare` whenever two versions of the same sequence must be reconciled: 154 store both and let the diff locate every difference. 155 156 When two versions of the same sequence disagree — a structure construct vs. a 157 UniProt reference, two structures, two pastes — store both, settle the 158 difference with `compare`, and adjudicate against the canonical reference from 159 `fetch-uniprot`. Base the verdict on tool output, not on reading the 160 sequences. When the tools locate the difference but cannot establish which 161 version is correct, that choice belongs to the user — present the diff and 162 ask. 163 164 ```bash 165 python <<skill_dir>>/sequence_toolkit.py compare <<wt_id>> <<mutant_id>> 166 python <<skill_dir>>/sequence_toolkit.py compare <<wt.fasta>> <<mutant.fasta>> 167 ``` 168 169 ### `generate` 170 171 Generate a mutant from a single-chain library ID or a TSV batch file. 172 173 Single-chain mode: 174 175 ```bash 176 python <<skill_dir>>/sequence_toolkit.py generate --id <<id>> --mutation <<mutation>> [--store <<output_id>>] [--format A0M] [--force] 177 python <<skill_dir>>/sequence_toolkit.py generate --id <<id>> --mutation <<mutation>> --output <<fasta_path>> 178 ``` 179 180 Batch mode (TSV columns: `source_id`, `mutation`, `output_id`): 181 182 ```tsv 183 source_id mutation output_id 184 <<source_id>> <<mutation>> <<output_id>> 185 ``` 186 187 ```bash 188 python <<skill_dir>>/sequence_toolkit.py generate --batch <<tsv_path>> --output <<fasta_path>> 189 ``` 190 191 Use `--store` to persist a single-chain result in the library (single-chain 192 mode only; ignored in batch mode). Use `--output` to write all generated 193 sequences to a multi-record FASTA file. 194 195 In batch mode an invalid row does not abort the run: the row's error is logged 196 with its TSV row number, remaining rows still process, and the summary reports 197 `rows_processed` and `rows_failed` (`success` is `false` and the exit code is 198 1 when any row failed). 199 200 Mutation tokens are combined with the `--sep` separator (default `_`). 201 202 The default substitution format is `C:A0M`, so every substitution token must 203 include a chain prefix. Use `--format A0M` for bare single-chain tokens 204 without the chain prefix. 205 206 ### `identify` 207 208 Identify substitutions, insertions, and deletions in mutants relative to the 209 first sequence. Arguments may be library IDs or FASTA file paths. 210 211 ```bash 212 python <<skill_dir>>/sequence_toolkit.py identify <<wt_id>> <<mutant_id>> [<<mutant_id>> ...] 213 python <<skill_dir>>/sequence_toolkit.py identify <<wt.fasta>> <<mutant.fasta>> [<<mutant.fasta>> ...] 214 ``` 215 216 ### `list` 217 218 List all library IDs and their lengths. 219 220 ```bash 221 python <<skill_dir>>/sequence_toolkit.py list 222 ``` 223 224 ### `delete` 225 226 Delete a library record. 227 228 ```bash 229 python <<skill_dir>>/sequence_toolkit.py delete <<id>> 230 ``` 231 232 ## Shared Mutation Notation 233 234 The default substitution token format is `C:A0M`: `chain:wt_position_mutant`. 235 236 ### Substitutions 237 238 `<<chain>>:<<wt>><<position>><<mut>>` — chain ID, WT one-letter residue, 239 1-based position, mutant one-letter residue. 240 241 Single-chain library records (from `fetch-uniprot` or `store`) have no real 242 chain: the chain letter in a `C:A0M` token is ignored and any prefix resolves 243 to the only chain. Use `--format A0M` to omit the prefix entirely. 244 245 To use bare single-chain tokens, pass `--format A0M`. 246 247 ### Insertions 248 249 `i<<chain>><<position>><<seq>>` — insert residues `<<seq>>` immediately after 250 `<<position>>` on chain `<<chain>>`. Use position 0 to insert before the first 251 residue. 252 253 ### Deletions 254 255 `d<<chain>><<position>><<seq>>` — delete residues `<<seq>>` starting at 256 `<<position>>` on chain `<<chain>>`. 257 258 Positions are 1-based. Combine tokens with `_`. 259 260 ## Output Schemas 261 262 Commands that produce results emit one `entry` record per result (`init` and 263 `delete` produce none). Every command closes with exactly one `summary` 264 record, including on failure and on argument/usage errors. Errors and 265 warnings are `log` records. 266 267 ### Sequence entry (fetch, store, list) 268 269 ```json 270 { 271 \"type\": \"entry\", 272 \"entry_type\": \"sequence\", 273 \"id\": \"<<id>>\", 274 \"length\": <<residue_count>> 275 } 276 ``` 277 278 Fetch and store add `\"source\"` plus the source identifiers (`\"accession\"` for 279 UniProt; `\"pdbid\"` and `\"chain\"` for PDB). 280 281 ### Mutant entry (generate, single-chain mode) 282 283 ```json 284 { 285 \"type\": \"entry\", 286 \"entry_type\": \"mutant\", 287 \"mutation\": \"<<mutation>>\", 288 \"source_id\": \"<<id>>\", 289 \"length\": <<residue_count>>, 290 \"stored_id\": \"<<output_id>>\" 291 } 292 ``` 293 294 `stored_id` is present only with `--store`. The full mutant `sequence` is 295 inlined only when the result is not persisted (no `--store`/`--output`). 296 297 Batch mode emits one entry per `output_id`: 298 299 ```json 300 {\"type\": \"entry\", \"entry_type\": \"mutant\", \"output_id\": \"<<output_id>>\", \"sequences\": {\"<<chain>>\": \"<<sequence>>\"}} 301 ``` 302 303 `sequences` is inlined only without `--output`. For single-chain records the 304 chain key is the synthetic `\"A\"`. 305 306 ### Segment entry (get --format jsonl) 307 308 ```json 309 {\"type\": \"entry\", \"entry_type\": \"segment\", \"sequence_id\": \"<<id>>\", \"start\": <<start>>, \"end\": <<end>>, \"residues\": \"<<segment>>\"} 310 ``` 311 312 ### Mutant entry (compare, identify) 313 314 ```json 315 { 316 \"type\": \"entry\", 317 \"entry_type\": \"mutant\", 318 \"index\": <<argument_position_wt_is_1>>, 319 \"sequence_id\": \"<<id>>\", 320 \"length\": <<residue_count>>, 321 \"edit_distance\": <<edit_distance>>, 322 \"threshold\": <<divergence_threshold>>, 323 \"divergent\": false, 324 \"description\": \"<<mutation description>>\", 325 \"events\": [ 326 {\"type\": \"substitution\", \"wt_residue\": \"<<wt>>\", \"position\": <<position>>, \"mutant_residue\": \"<<mut>>\"} 327 ] 328 } 329 ``` 330 331 A pair is `divergent` when the edit distance exceeds `max(50, 10% of the mean 332 sequence length)`. When `divergent` is `true`, `description` and `events` are 333 `null`. `compare` adds `wt_id` to the entry. 334 335 ### Summary 336 337 Every command closes with exactly one summary record carrying `command`, 338 `success`, and per-command statistics. On failure the summary follows the 339 error log record and has `\"success\": false`: 340 341 ```json 342 {\"type\": \"summary\", \"command\": \"<<command>>\", \"success\": true, \"...\": \"...\"} 343 ``` 344 345 `generate` reports `records_written` (0 when nothing was persisted) and 346 `output_file`; batch mode also reports `rows_processed` and `rows_failed`. 347 `compare`/`identify` report `mutants_processed` and `exceeded_threshold`; 348 fetch/store report `length`; `get` reports `segments`. 349 350 ### Errors and warnings 351 352 Emitted as log records: 353 354 ```json 355 {\"type\": \"log\", \"level\": \"error\", \"msg\": \"Sequence '<<id>>' not found in library\"} 356 ``` 357 358 ## Recommended Workflow 359 360 1. Fetch: `python <<skill_dir>>/sequence_toolkit.py fetch-uniprot <<accession>>` 361 2. Inspect: `python <<skill_dir>>/sequence_toolkit.py get <<id>> <<position>>` 362 3. Generate: `python <<skill_dir>>/sequence_toolkit.py generate --id <<id>> --mutation <<mutation>> --store <<output_id>>` 363 4. Verify: `python <<skill_dir>>/sequence_toolkit.py identify <<id>> <<output_id>>` 364 365 ## Best Practices 366 367 - Treat toolkit output as final: build on it directly, and do not re-derive or 368 re-verify results by reading the raw sequence. 369 - Reference sequences by library ID or file path; avoid pasting long sequences inline. 370 - Write data to files only via `--output` flags; never redirect stdout — stdout 371 carries the JSONL record stream, not file content. 372 - Provide sequences as FASTA files whenever possible; use `--seq` only for short fragments. 373 - When pasting is unavoidable, always verify: pass `--length` or `--crc64` from source 374 metadata.
